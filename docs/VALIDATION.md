# Validation and release status

This is an initial implementation, not a claim of a completed security audit or a production-proven server image. No connection to your server has been made and no server settings have been changed by this development session.

## Checks completed locally

- **78 Python standard-library tests pass**, covering rejected input/injection, private policy files, user-owned symlink handling, IPv4/IPv6 rules, default closed app/panel/DB ports, SSH include repeatability, role rendering, V2Ray client settings, per-user admission/stale PIDs, snapshot restore, timer failure, overlapping-change refusal, immediate failed-apply recovery and fresh-login confirmation. The actual PAM helper's file lock was also exercised with eight simultaneous processes: exactly three were admitted for a limit of three, using unprivileged temporary paths and a process-lookup fixture.
- New tests exercise the actual GitHub archive extractor against valid sources, path traversal, symlinks, hard links, duplicate entries and missing tool files. MongoDB lifecycle tests use command adapters/temporary files to verify package-time masking, signing-key checks, refusal to overwrite data, restricted bootstrap ordering, failure cleanup and credential-free command arguments/state. A real Node runtime evaluates the generated app-user JavaScript against a mocked database API to check database-scoped roles and password-prompt logic; this is not a live MongoDB authentication test.
- Terminal UI tests cover field errors/defaults/cancellation, root setup pausing before access restrictions, resuming through login verification and plan review, pending-change routing, explicit secret export, confirmation IDs, optional-service start guards, and real management-file locking only during command dispatch. A real PTY smoke test of `scripts/preview_terminal.py` exercised menu navigation, an invalid SSH port, form cancellation, MongoDB forms, recovery navigation and exit. Preview commands were disabled and all state was temporary; no host configuration changed.
- A real local OpenSSH **10.2p1** parser accepted the generated SSH config and effective administrator/developer/SFTP restrictions. It was run only in parser mode against temporary config/host keys; no local SSH service was started or changed. This does not replace the Ubuntu 24.04 package test.
- Official **V2Ray 5.53.0, darwin/arm64** accepted a generated server configuration using `v2ray test -c`. Its archive SHA-256 matched GitHub's published release-asset digest. This verifies config compatibility on that binary, not Linux systemd/runtime deployment or end-to-end proxy connectivity.
- `bash -n install.sh` and Python byte-compilation pass.

Run the source tests on a development machine without root:

```bash
python3 -m unittest discover -s tests -v
python3 -m compileall -q server_guard tests
bash -n install.sh bootstrap.sh
```

## Required disposable Ubuntu 24.04 VM checks

There was no available running Ubuntu VM/container engine in the development environment, so the following integration checks remain **unexecuted**. Use a disposable Ubuntu 24.04 x86_64 VM with working systemd, a provider console and snapshots before applying this to production. Do not test firewall/PAM changes on your only access path.

1. Follow README steps 1–2. Prove root/password access remains until key/sudo proof is recorded. Confirm `apply` refuses without that proof. Verify the generated effective SSH policy using `sshd -T -C user=admin,host=localhost,addr=YOUR_IP`.
2. Apply without confirming. From the provider console verify the timer is active and the snapshot exists. After ten minutes, verify SSH/firewall/PAM files and original firewall activation are restored. Repeat with an initial UFW policy and `apply --replace-ufw`.
3. Apply again and confirm from a new key login. Confirm the old connection, a password-authenticated connection, a non-admin account and a wrong transaction ID cannot cancel the timer. Reboot with a pending transaction and verify the countdown/recovery restarts.
4. Force an invalid SSH include or nft syntax error in an isolated copy. Verify immediate rollback and preservation of unrelated firewall tables. Check failed restores leave the pending snapshot available for retry.
5. Open the configured number of independent transports with `ssh -o ControlMaster=no -o ControlPath=none ... sleep 300`; the next must be denied. Repeat with PTY shells, `ssh -T ... sleep 300`, SFTP, `ssh -N -L ...`, and simultaneous connection attempts. Verify different users have independent caps, a dead transport releases its slot, and multiplexed concurrent channels cannot bypass `MaxSessions 1`. Monitor `/run/server-guard/sessions.json` and the SSH journal. Verify the PAM parent PID/token corresponds to a transport-lifetime monitor on the actual Ubuntu package. A mismatch here must be fixed before claiming enforcement.
6. Test SFTP chroot upload/download and rejection of shells, traversal outside the jail, port forwarding and terminal allocation. Validate every chroot path component is root-owned and not group/world-writable.
7. Test IPv4 **and IPv6** from another host: initially only SSH should be reachable. After `web enable`, only intentional SSH/80/443 listeners should be reachable. The panel, DB and V2Ray backend must be unreachable publicly; HTTPS panel access through the tunnel must work. Include provider rules and interfaces in the test. A local `ss` listing alone cannot prove external exposure.
8. Verify ICMPv6 neighbor discovery, IPv4/IPv6 PMTU, DHCP renewal, DNS, package updates and server time synchronization still work. Verify no routing/bridge workloads are expected. Starting a container runtime afterward is outside this release's supported deployment.
9. Trigger a small controlled sequence of failed logins from a separate test IP, check the Fail2Ban jail's actual ban/rule and later unban. Do not ban your only administration source. Confirm IPv6 bans too.
